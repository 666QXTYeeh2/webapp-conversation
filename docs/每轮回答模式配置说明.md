# 每轮回答模式配置

导入并发布 `通用知识问答助手 V2.2 每轮模式.yml`，检查模型及知识库绑定。若导入为新应用，更新 `.env.local` 的 `NEXT_PUBLIC_APP_ID` 和 `NEXT_PUBLIC_APP_KEY`，然后重启服务。配置中心应用保持原有配置。

网页每轮发送当前模式，继续使用原对话编号。服务端将问题与模式封装，工作流先解析本轮模式，再执行原有输入校验、文件处理和模式分流。开始节点不再要求 `answer_mode`。直接从 Dify 调试输入普通问题时默认快速问答。

必须配套发布 V2.2 工作流后再使用新版代码，旧工作流不能解析请求封装。页面和分享显示原始问题；Dify 后台的原始请求日志中会看到封装字段。当前所选模式持续用于后续发送，切换模式本身不发送消息。

智能推理保留 V2.1 的分析摘要和最终答案输出。历史对话是否可继续使用新流程取决于 Dify 版本及已发布流程的会话兼容性，需在实际部署验证。
